# 검증 및 문제 해결

## 1. 제출 전 정적 검사

```bash
cd <프로젝트>/final
./check_project.sh
```

ROS 워크스페이스를 다시 빌드할 수 있는지 확인한다.

```bash
./02_build_ros_ws.sh
```

## 2. 필수 토픽 확인

Isaac과 Nav2를 실행한 뒤:

```bash
ros2 topic list | sort
ros2 topic hz /clock
ros2 topic hz /scan
ros2 topic hz /amr2/scan
ros2 topic echo /amr1/world_pose --once
ros2 topic echo /amr2/world_pose --once
```

주요 토픽:

- `/map`, `/clock`
- `/cmd_vel`, `/odom`, `/scan`, `/tf`
- `/amr2/cmd_vel`, `/amr2/odom`, `/amr2/scan`, `/amr2/tf`
- `/amr1/world_pose`, `/amr2/world_pose`
- `/traffic_conflict/status`, `/traffic_reservation/status`

## 3. 자주 발생하는 문제

### Isaac `python.sh`를 찾지 못함

```bash
export ISAAC_SIM_DIR=/실제/isaacsim/경로
./03_run_isaac.sh
```

### Nav2 실행 전에 workspace build 오류

```bash
./02_build_ros_ws.sh
```

### GUI에서 Flask 또는 rclpy import 실패

```bash
sudo apt install python3-flask
source /opt/ros/humble/setup.bash
source ros2_ws/install/setup.bash
python3 -c 'import flask, rclpy; print("OK")'
```

### OCR에서 `NO_PLATE_DETECTED`

- 카메라 영상 토픽과 프레임 발행 여부를 확인한다.
- 이름표가 카메라 시야 중앙에 들어왔는지 확인한다.
- OCR 가상환경을 다시 확인한다: `./01_install_ocr_ros.sh`
- `cv2.aruco`가 필요한 경우 contrib 버전이 설치되어야 한다.

### 두 PC 사이에 토픽이 보이지 않음

- 양쪽 `ROS_DOMAIN_ID`가 115인지 확인한다.
- 양쪽 `RMW_IMPLEMENTATION`이 `rmw_fastrtps_cpp`인지 확인한다.
- `ROS_LOCALHOST_ONLY=0`인지 확인한다.
- VPN과 방화벽, Wi-Fi AP의 client isolation을 확인한다.

### GUI 포트 5000 충돌

기존 GUI 프로세스를 먼저 종료한다. 어떤 프로세스가 사용 중인지 확인:

```bash
ss -ltnp | grep ':5000'
```

### `ExternalShutdownException`

다른 터미널의 종료, ROS context shutdown, 중복 실행 스크립트가 원인일 수 있다. 동일 AMR 미션이 중복 실행되지 않았는지 확인하고 `./00_stop_all.sh` 후 권장 순서로 다시 시작한다.

### AMR이 정지 상태로 유지됨

```bash
ros2 topic echo /traffic_conflict/status
ros2 topic echo /traffic_reservation/status
```

`OWNER_STALE_FAILSAFE_HOLD`이면 실제 AMR 위치를 확인한 뒤 관련 프로세스를 모두 재시작한다. 안전 상태를 확인하지 않고 강제로 예약을 해제하지 않는다.

## 4. 기능별 합격 기준

| 기능 | 확인 기준 |
|---|---|
| Isaac 실행 | 병원 Stage와 AMR 2대가 나타나고 `/clock` 발행 |
| Nav2 | 두 AMR의 map·odom·scan과 NavigateToPose 사용 가능 |
| OCR | 세 환자 중 선택한 이름표 판정 결과 출력 |
| 결합 | 침대 하부 진입 후 리프트·FixedJoint/자기 결합 유지 |
| 충돌 회피 | 경로 충돌 시 후순위 대기, 선행 통과 후 재개 |
| 엘리베이터 | 탑승 AMR만 단계별 이동하고 층 전환 완료 |
| GUI | AMR·환자 선택, 이동/복귀 상태 표시 |
| 트레이 | 양쪽 ArUco pair 인식, 2대 결합 후 공동 운송 |

## 5. 시연 직전 점검

1. 남은 ROS·GUI 프로세스를 종료한다.
2. 두 PC의 domain/RMW/네트워크를 확인한다.
3. Isaac을 먼저 실행하고 PLAY 상태를 확인한다.
4. AMR1·AMR2 Nav2 초기 pose를 확인한다.
5. 충돌 관리 노드를 실행한다.
6. GUI 또는 미션은 마지막에 실행한다.
7. 첫 AMR이 충전 구역을 벗어난 뒤 두 번째 미션을 시작한다.
