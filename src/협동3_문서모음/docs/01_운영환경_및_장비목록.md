# 운영환경 및 장비 목록

## 1. 소프트웨어 환경

| 구분 | 프로젝트 기준 | 용도 |
|---|---|---|
| 운영체제 | Ubuntu 22.04 LTS | ROS 2 및 Isaac Sim 실행 |
| ROS 2 | Humble | 노드·토픽·액션 통신 |
| Isaac Sim | 5.1 | 병원 디지털 트윈과 물리 시뮬레이션 |
| Python | ROS 측 3.10, Isaac 내장 Python | GUI·OCR·ROS 노드·시뮬레이션 런타임 |
| ROS Domain ID | 115 | 두 PC와 모든 ROS 노드 통신 통일 |
| RMW | `rmw_fastrtps_cpp` | DDS 통신 구현체 |
| GUI | Flask 3.x | 관제 화면 제공 |
| OCR | PaddleOCR 3.1.1 | 환자 이름표 인식 |
| 영상처리 | OpenCV contrib 4.10.0.84 | ArUco 및 영상 처리 |

세부 Python 버전은 `requirements.txt`, `requirements_ocr_ros.txt`를 따른다. ROS 패키지는 pip가 아니라 Ubuntu/ROS 패키지 관리자로 설치한다.

## 2. 시연 장비 구성

| 장비 | 수량 | 역할 | 비고 |
|---|---:|---|---|
| Isaac Sim 실행 PC | 1 | 병원 USD, AMR 2대, 센서·물리 실행 | NVIDIA RTX GPU 권장 |
| 관제/GUI 실행 PC | 1 | GUI, 미션 실행 및 모니터링 | 동일 PC 실행도 가능 |
| 유선 또는 안정적인 LAN | 1식 | 두 PC 간 ROS 2 DDS 통신 | 동일 서브넷 권장 |
| 모니터·키보드·마우스 | 1식 이상 | 시연 조작 및 로그 확인 | 다중 터미널 사용 |

이 프로젝트는 디지털 트윈 시연이므로 물리 AMR, 실물 LiDAR, 실물 카메라는 필수 제출 장비가 아니다. 시뮬레이션 내 장비는 다음과 같다.

- AMR 2대
- 환자 침대 3대
- 전방 RGB 카메라
- AMR별 360° LiDAR/LaserScan
- 자기 결합 및 리프트 구조
- 병원 1·2층과 엘리베이터
- 협동 운송용 트레이와 ArUco 마커

## 4. 네트워크 공통 설정

두 PC를 사용할 경우 양쪽 터미널에 같은 값을 사용한다.

```bash
export ROS_DOMAIN_ID=115
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=0
```

방화벽, VPN, 서로 다른 Wi-Fi 격리 설정은 DDS discovery를 막을 수 있다. 통신이 안 되면 먼저 양쪽 PC에서 `ros2 topic list` 결과를 비교한다.

## 5. 실제 사용 장비 목록

| 장비 | 수량 | 사양 | 용도 |
|---|---:|---|---|
| Isaac Sim 실행 노트북 | 2대 | RAM 32GB, NVIDIA GeForce RTX 5080, VRAM 16GB | Isaac Sim 병원 환경 실행, AMR 시뮬레이션, ROS 2 및 GUI 구동 |
| TP-Link 유선 네트워크 허브 | 1대 | 유선 LAN 연결 지원 | 두 노트북 간 ROS 2 DDS 통신망 구성 |
| LAN 케이블 | 2개 | 이더넷 케이블 | 각 노트북과 TP-Link 허브 연결 |

두 대의 노트북을 TP-Link 유선 네트워크 허브에 연결하여 동일한 로컬 네트워크를 구성하였다. 양쪽 노트북은 동일한 `ROS_DOMAIN_ID=115`와 `rmw_fastrtps_cpp` 설정을 사용하여 AMR 상태, 센서 데이터, Nav2 명령 및 GUI 정보를 주고받았다.
